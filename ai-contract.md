## AI Contract

The following document details the set of rules regarding LLM use during the Software Architecture course that Team 67 will abide by.

1. Ideation & Architecture

    We are allowed to use LLMs to explore different architectures that we would normally be unaware of. AI can also be used as a helper to explore documentation in a more condensed way. Additionally, LLMs can be used to explore blindspots, overlooked considerations or mistakes in existing work. However, LLMs are not allowed to make any significant decisions regarding the architecture or logic of the system.

2. Coding

    LLMs can be used to generate code with clearly delineated coding tasks, to implement well defined requirements and in testing, either helping with the testing harness or the tests themselves. However, the author of a commit is responsible for the code they commit and they must wholly understand any line of code that is submitted. "Vibe coding" is not allowed.

3. Code reviews

    AI cannot be used to make a decision in a PR. LLMs can be used to highlight important changes, but the final decision must be taken by a human.

4. Presentations & Report

    We will not use AI to generate large chunks of text for the report or in presentations. AI can be used to improve grammar and to help with the general flow of sentences. In presentations, AI can be used to generate graphics or diagrams. Completely AI-generated presentations are not allowed.
